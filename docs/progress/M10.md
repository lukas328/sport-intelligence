# M10 Data and training: report

Date: 2026-11-03 · Status: **done**, with one measurement open: the data assistant's accuracy and
latency with the real model need an API key (OPEN_QUESTIONS Q-M10-1)

## Delivered
| Item (PLAN M10) | Result |
|---|---|
| Ask your data 5.1 | ✅ chat per team for coaches, analysts and specialist coaches. Claude (tool use, effort low, cached prompt, refusal fallback) chooses typed queries only (`list_matches`, `query_events`, `aggregate_metric`, `compare_periods`, `find_plays`, `get_clips`, `list_insights`; no SQL) and answers through `final_answer` with value, sample, clips and optional chart. **Number validator**: every number of the answer must come from a tool result of the question (ratios also as rounded percentages, dates by their parts); one correction round, then an honest "cannot answer reliably" with an answerable suggestion. Not answerable questions (no data, names, the future) get a suggestion. Jersey numbers only, no names leave the organisation. Every question is logged with tool calls, tokens, cost, latency, validator status and the user's rating; monthly cost cap per plan (Team 5, Club 25 USD). ADR 021 |
| Evaluation set 5.1 (≥ 60 questions in CI) | ✅ 62 questions (55 answerable, 7 deliberately not) on a deterministic season of 8 matches and about 560 events; expected values computed from the raw events with plain Python. CI replays each question's tool plan with a scripted model through the real API: **62 of 62 correct, no invented number**. `pytest -m live` runs the same set against the model and writes `docs/perf/assistant-eval.md`; not run here (no key) |
| Statistics matrix 5.4 | ✅ rows (player number, position, play, match, opponent, half, 10-minute phase, shot zone, shot type) × up to 8 metrics × filter (team, last matches, half); every cell lists its events and the clips with video time (P2); templates per team; CSV and Excel export with a guard against spreadsheet formulas |
| Export 5.4 | ✅ Sportscode-compatible XML per match (events with video time and clips with their tags as instances with code, start, end and labels; rows with colours), CSV of all events (jersey numbers, no names) |
| Import 5.4 | ✅ Sportscode XML as own tags: each instance a clip, code and labels as tags (labels grouped into tag sets); safe XML parsing (no entities), size and count limits. **Round trip export, import, export is lossless** (tested). CSV of match feeds since M4; video import per direct link since A1, partner APIs (Veo, Spiideo, Hudl, asport) as stubs behind the adapter (ADR 018) |
| From problem to training 5.6 | ✅ "Train this" on a weakness: one click creates a session with the suggested drills, a playlist with the evidence scenes (shared with the players) and optionally an assignment for the team. The insight's metric is followed: up to 5 matches before against the matches since, per match for counts, labelled "observation, not proof", with a small-sample note below 10 events. Insight topics map to the drill library's focus areas |
| Lean training planning 5.7 | ✅ sessions with date, time, place, notes and drills from the library (stored as a snapshot so later library changes keep the plan), reordering, PDF for the hall in three languages; attendance for sessions **and** matches: players and parents reply on "My dates", staff record present, late, excused, injured or unexcused (free-text reason, no diagnoses); calendar subscription per team (ICS feed, only the token's hash is stored, a new link replaces the old); ICS import of sessions (known UIDs are updated). Spond and ClubCorner remain adapter stubs; ICS covers both until API access exists (P9) |

  two drills, PDF, calendar feed, matrix, assistant without key, empty schedule) with axe checks.
- Site: three new help articles in de, fr, en (19 in total), mapped from the new screens.

## Vision-Check
- P1 Automatisch zuerst: eingehalten. The matrix and the assistant work on automatic and tagged events
  alike; nothing needs extra tagging. Formation answers wait for the analysis instead of tagging.
- P2 Jede Zahl führt zum Video: eingehalten. Matrix cells and assistant answers list their clips;
  events without video time are counted but not offered as clips.
- P3 Ehrlich statt beeindruckend: eingehalten. The validator blocks numbers no tool returned, answers
  state their sample, before/after is labelled an observation with a small-sample note, the
  assistant's model accuracy is reported as not yet measured.
- P4 Amateur zuerst: eingehalten. One-click focus from an insight, session PDF for the hall, replies
  from the phone, calendar subscription instead of a separate app.
- P5 Team-Plattform, Torhüter als Modul: eingehalten. Save percentage per zone and goalkeeper drills
  appear in matrix, assistant and focus without a separate goalkeeper product.
- P6 Nachwuchs schützen: eingehalten. Parents reply for their children; the assistant sends jersey
  numbers only; attendance reasons are free text without diagnoses.
- P7 Datenschutz als Standard: eingehalten. Conversations are private per user, model calls carry no
  names, the calendar link is a hashed secret that can be replaced, CSV exports use numbers.
- P8 Handball-Sprache: eingehalten. Rechtsaussen, Rückraum, Kreis, 7 m, Gegenstoss in questions,
  matrix and texts in de-CH, fr, en.
- P9 Partner statt alles selbst: eingehalten. Sportscode exchange, ICS in and out, Spond and
  ClubCorner behind the adapter.
- P10 Schnell und günstig: eingehalten. Low effort, cached prompt, monthly cap per organisation, the
  arithmetic runs in our own query layer.

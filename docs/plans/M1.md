# M1 plan: accounts, tenants, roster

Acceptance (BRIEF 14): a new user creates club, team and roster in under 5 minutes; role tests are green.

## Backend
1. Settings for auth, e-mail, rate limits; non-superuser DB role `handball_app` so RLS really applies (ADR 005)
2. Models + migration 0002: users, auth_sessions, auth_tokens (magic link), organizations, org_memberships,
   teams, seasons, memberships, players, roster_entries, invitations, consents, audit_logs; RLS policies
3. Security core: Argon2 passwords, opaque session tokens (hashed in DB), HMAC-bound CSRF double submit,
   Fernet-encrypted TOTP secrets, Redis rate limiter (memory in tests)
4. E-mail port: SMTP adapter (mailpit), memory adapter (tests); de-CH/en/fr templates (ADR 009)
5. Auth API: register, login (+ TOTP step), logout, magic link request/consume, me, TOTP setup/enable/disable
6. Policy layer: one permission table `role × action`, enforced in services; 2FA requirement for org_admin
   with grace period
7. Org API: create (creator becomes org_admin), list mine, read, update, logo upload (PNG/JPEG/WebP, ≤ 1 MB)
8. Teams + seasons API; team setting `players_see_team_stats` (default off for youth teams)
9. Roster API: players + roster entries, CSV import with dry run and row errors, consent records
10. Invitations: create (org_admin; coach for own team), e-mail, preview, accept (existing or new account), revoke
11. Audit log for sensitive actions
12. Tests: policy test matrix (role × endpoint), cross-tenant suite (API + RLS), service tests; coverage ≥ 80 %

## Frontend
13. UI primitives (shadcn-style: button, input, label, card, alert, table, field)
14. Same-origin API proxy (`/v1/*` rewrite), typed client with CSRF header, session-aware server fetch
15. Pages: register, login (+ TOTP), magic link, onboarding wizard (club with logo and colours → team →
    roster form + CSV → invites), app home with teams, roster page, invitation accept, settings (people, 2FA)
16. Playwright: full onboarding flow timed (< 5 min), CSV import, invite flow via mailpit, axe on every page

17. ADR 008 (auth and sessions), ADR 009 (e-mail provider), progress report M1
